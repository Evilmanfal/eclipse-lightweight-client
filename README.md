# Eclipse Native 0.8

Independent Windows x64 Discord client in Rust, egui and OpenGL. Run **Eclipse.exe** from this folder. No Electron, WebView, installation, service or automatic startup is required. Installed Discord is untouched. Renamed from Feather; one current `eclipse-native` folder is retained. Your existing preferences are carried over to `eclipse-settings.json`. The orange/red eclipse icon is embedded in the EXE and used by the window/taskbar.

Use Eclipse's token-entry screen or the offline preview. Credentials remain in memory and never enter preferences. Personal-account access is unofficial; Discord can change its APIs or restrict accounts using them.

## Push to talk

Gear → **Voice & Video** → **Push to Talk** → **Record hotkey**, then press and release a key, mouse button or chord. Ctrl, Shift and Alt work alone or in combinations. Recording waits for held keys to be released, then saves on release so modifiers are not mistaken for an incomplete chord. Escape cancels. The default is F8. The binding can change during a call. Releasing the key or a required modifier closes the microphone gate; mute, deafen and server restrictions still apply. It works with Eclipse in the background. Other apps can receive the same key.

The hotkey, devices, themes and other local preferences save automatically to `eclipse-settings.json` beside the EXE. No keystroke history is recorded. Other global shortcuts are unsupported. Ctrl+wheel zooms the whole interface from 75–150%; Ctrl+0 resets to 100% (Ctrl+Plus/Minus also work). The scale saves with Appearance preferences. At high zoom, the member panel temporarily hides to leave room for chat and returns when space allows. Focused shortcuts include Ctrl+, for settings and Ctrl+Shift+M / Ctrl+Shift+D for mute/deafen.

## Calls

Actual Discord Gateway/voice signaling, DAVE encryption, Opus audio and H.264 video are implemented natively. The central call view has participant tiles, speaking borders and bottom mute/deafen/camera/share/disconnect controls. The layout follows Discord, but is **not pixel-identical**. **Live Discord interoperability remains unverified.** Local media tests cannot prove production-service compatibility or hardware capture quality.

- Start a DM Call/Video, answer an incoming call, or select a server voice channel. Your avatar/name appear beneath the active voice channel, with a green avatar ring and microphone indicator driven by actual local transport speaking activity. Mute/deafen/PTT and server restrictions gate the indicator. A persistent voice connection card offers call view and disconnect. Stage channels are unsupported.
- Choose audio devices, gains and processing in Voice & Video. Camera uses the system-default camera. Pre-call mute/deafen carry into the call.
- Screen sharing has a native source picker and an explicit Go Live action. System audio is opt-in; it includes other applications and excludes Eclipse's process tree, even for a single-window share.
- Sharing supports 720p at 15/30 fps and 1080p/60 options for reported Nitro or eligible boosts. No 4K encoder is included. One Go Live stream is negotiated at a time.

Mute/unmute and deafen/undeafen each have a distinct, original short native feedback sound, including keyboard toggles. User Settings → Notifications → Mute/deafen feedback sounds controls them. These are Eclipse earcons, not redistributed Discord audio. No signed-in session, microphone, camera or desktop capture was used during agent validation. See VALIDATION.md for measured checks.

Voice channels list everyone connected, including people using the official Discord client or other devices, with muted/deafened, camera and LIVE indicators; Eclipse learns this from Discord's voice states whether or not it has joined. Push to talk gates an always-open microphone (the key is polled every 4 ms), so speech starts and stops without reopening audio devices; short rising/falling tones play on press and release, following the feedback-sound setting. Join feedback plays once when voice transport becomes ready. Leave feedback plays once after that connection ends. Failed attempts and offline previews stay silent. All six original PCM cues follow Notifications → Voice connection, mute and deafen sounds.

## Settings and menus

User and Server Settings use matching centered panels, grouped navigation and rounded content cards. Navigation rows highlight on hover without repeating their label in a tooltip. Click the dark backdrop, press Escape or use × to close. Friendly account/device/service names replace raw numeric fields; technical IDs are under Developer mode. Language and processing controls use readable labels. Performance offers Smooth, Balanced and Save memory presets.

User Settings has 26 sections grouped under Your Account, Privacy & Safety, Billing & Nitro, App Settings, Activity and Eclipse. Account & Profile combines the previous My Account and Profiles pages. Native controls cover profile display name, pronouns, bio, avatar/accent; supported account preferences; appearance, accessibility, chat, voice devices/processing, hotkeys, plugins, themes and performance. Account changes require Save/action; local preferences save automatically.

Connections, devices, authorized apps, subscriptions, gift inventory and boosts retrieve account information. Security/MFA, billing, family controls and incomplete flows link to Discord. Language updates the account locale; Eclipse's interface remains English. **Not every Discord setting is implemented natively.**

Click the server icon or name at the top of the channel list to open its anchored menu, with Server Settings, Members & Roles and Notification Settings. Server Settings has 21 sections grouped under Server, Expression, Moderation, Community and Apps & Sharing. Implemented edits include server metadata/icon/system channels, role names/colors/permissions, member role assignment/moderation, basic channel creation/editing, emoji upload/deletion, sticker deletion, ban revocation, widget/vanity and notifications. Permissions and role hierarchy gate actions. AutoMod/onboarding/welcome and several resource sections are read-only. Channel permission overwrites, role reordering, integration/webhook creation and community setup remain incomplete.

Click a server member, avatar or author name for a profile popout anchored beside that account. Clicking the same person again, an outside click or Escape dismisses it. The pin icon opens pinned messages as a dropdown anchored beneath it; drag its bottom edge to resize (the height is saved), and click a pin to jump to it in the conversation (older pins load the surrounding messages, with Jump to present to return). Right-click → Profile, or a popout avatar, opens a full centred profile with bio, member-since dates, roles, connections and mutual servers/friends. Profiles use the account theme colours as a gradient with the banner fading into it. Chat avatars omit presence dots. Friends is a compact list with message/profile icons and an Active Now column of friends' current activities. Ctrl+V in the message bar attaches copied files or images (screenshots, browser images); text pastes as usual. The account bar at the bottom left spans the server rail and channel list: your nameplate is its background (or the theme surface colour without one), with your avatar, name and status, plus activity, mute and deafen controls (with input/output device menus) and settings. Members show avatars, statuses, role colors/groups. The conversation header has one search box ("Search <server name>" in servers, "Search this conversation" in DMs) that filters both messages and the member list, with small pin and member-list icons beside it. Profiles use Discord-supplied badges, global/server banners, profile colors, pronouns/bio, role chips, avatar decorations, server tags, nameplates and display-name fonts/colors. Animated artwork shares the bounded native media cache. Status badges are painted over avatar decorations and profile-effect artwork. Chat avatar clicks use distinct hit regions even when one author has several messages on screen. Profile effects use the provided preview/reduced-motion artwork when Discord returns a matching effect configuration; that endpoint and live cosmetics remain unverified.

Thirteen licensed display-name font families are bundled, with Unicode fallbacks; Néo-Castel (ID 7) and the deprecated Compagnon (ID 5) fall back to the regular font. Native name gradients/glows and Gummy squash/stretch are approximations; Discord's exact effect-layer choreography remains incomplete. Prism colors wrap continuously, and animated names follow the selected FPS cap. Font licenses and source hashes are in assets/fonts/. No paid item or badge is fabricated for an account. The selected guild roster loads progressively and is bounded to 1,000 members. Completeness depends on Discord's responses. Unknown presence is not treated as confirmed offline.

Hold Shift while hovering a message to reveal compact edit/delete buttons. Edit is available for your own messages; delete follows ownership/server permissions and still asks for confirmation. Right-click messages, author names/avatars, members and channels. Direct-message rows expose the recipient actions directly, without an extra Recipient submenu. Menus include replies, copying, reactions, permitted edits/deletes/pins, mark unread, profiles, DM/friend/block actions, local volume and permitted server roles/moderation. DM rows accept clicks across their width. The + beside Direct messages opens an anchored, searchable name/@username dropdown (outside click or Escape dismisses it) for friends, DM recipients and loaded server members, with self/blocked accounts excluded. It does not offer a global Discord user directory. Decorated channel names use installed Windows font fallbacks.

Shop cards resolve each product’s preview, decoration hash, matching profile-effect configuration or nameplate asset. Quests resolve hero/reward filenames and CDN-root paths against the matching quest. Missing live metadata shows artwork unavailable rather than substituting an unrelated product illustration. Public asset routes were checked against [Discord’s client](https://discord.com/app) on October 8, 2026; account-specific availability remains unverified.

## Native plugin equivalents

Vencord needs Discord's web renderer; OpenAsar needs Electron's app.asar. Their packages/JavaScript plugins cannot run directly here. These original native equivalents are selectable under Plugins:

| Feature | Behavior |
|---|---|
| Spotify Controls | Windows Spotify desktop media-session controls: previous/play/pause/next, seek, shuffle, track repeat. Actual Spotify interoperability is unverified. |
| SpotifyCrack | Eclipse never auto-pauses Spotify while speaking. Premium spoofing and free Listen Along are **not implemented**. |
| VolumeBooster | Per-user and watched-stream volume up to 1,000%, clipped to valid PCM. Disabling clamps to 200%. Device gains remain 0–200%. |
| Silent Typing | Default on: no typing notifications. Disabling enables rate-limited typing notifications. |
| Read All | Text button labeled Read All directly beneath the moon icon acknowledges known channel message IDs through Discord's bulk endpoint. |
| Message logger | Edits and deleted messages stay inline in red; previous edit text expands beneath the message. Up to 200 snapshots remain in RAM, cleared on logout/exit/disable. The separate log window/counter is removed. Unseen history cannot be recovered. |
| MessageClickActions | Double-click reply, Ctrl-click copy, Alt-click your own message to edit. |
| GameActivityToggle | Beside mute/deafen; updates Discord's activity-visibility preference. No game-process detection. |

The default **Material Black** theme takes inspiration from [MaterialDiscord](https://github.com/CapnKitten/Material-Discord): neutral black surfaces, grey accents, plain message rows, pill selections/buttons and a rounded composer. It is drawn natively in Rust. Account cosmetics, role colors, status indicators and official Discord artwork retain their colors. The previous default palette upgrades automatically while keeping hotkeys and other preferences; custom themes stay intact.

Themes include presets, native JSON import/export and selected literal Discord CSS color variables. Full CSS layouts, remote imports and executable themes are unsupported. JSON display plugins replace incoming text locally, preserving original/outgoing content; see examples/display-plugin.json. This is not a general Vencord runtime.

OpenAsar-like performance goals are addressed through native rendering, bounded caches/queues/history, idle repaint, reduced motion and animation FPS controls. No Discord installation is patched.

## Friends, Nitro, Shop, Quests and media

Friends has Online/All/Pending/Blocked/Add Friend, search, requests, profiles and DMs. Nitro shows reported subscription status and supported benefits. Existing entitlements determine message length/emoji/avatars/streaming; Eclipse does not grant subscriptions. Message limits are 2,000 or 4,000 for reported full Nitro; Discord enforces uploads.

Nitro uses official Discord Wumpus artwork. Shop and Quests include official Discord artwork as their default banners, with bundled assets for offline use. Live collections/quests use their account-supplied banner/card artwork when available. Asset URLs and SHA-256 hashes are recorded in assets/discord/SOURCES.json; Discord retains the rights to its artwork. Shop has a featured banner, collectible-type tabs and a responsive product-card grid. Quests has a featured banner, Discover/Accepted/Completed tabs and cards for artwork, rewards and account progress. These native layouts follow Discord's organization, without claiming pixel-identical rendering. Shop retrieves the live catalog; checkout uses Discord. Quests retrieves offers/progress and supports enrollment; detection, watch tracking, completion and reward claiming use Discord. Offline example cards are explicitly labeled and disabled; they never represent account eligibility, purchases or earned progress.

Messages from today show only local time. Earlier local calendar days show the time plus date (for example `16:21 · Oct 7, 2026`). Windows timezone/DST conversion determines the day, including near midnight. Timestamp labels have a bounded in-memory cache that refreshes on date/timezone changes.

**Enter sends; Shift+Enter inserts a new line.** Unfocused Enter and IME composition do not send. Server/group/direct messages use plain rows without grey message bubbles. Mention emphasis and inline edited/deleted styling remain. Server text and voice channels use 30-point rows with three points between them. The server list starts directly below the server header; its old search field and redundant Conversations label are removed, and the channel viewport uses the recovered space. DM search stays available as Find a conversation. Server member rows also use smaller avatars and tighter spacing. The server rail scrolls with the wheel and has no visible scrollbar. Its 44-pixel server icons have tighter spacing and gently enlarge on hover without moving neighboring servers. Reduced motion disables the transition. The selected DM moon uses a grey background and black crescent.

Small emoji/GIF icon buttons sit inside the message bar beside Send, with an upload icon at the left. Both pickers open above their button as anchored popups; outside click, Escape, × or clicking the same button closes them. They follow the composer when resized/zoomed and close when changing conversations or opening settings. Rendered images/GIFs omit their raw URLs and attachment hyperlinks; right-click the media to open it or copy its link. Ordinary links and links with inline images disabled remain visible. Emoji/GIF pickers, one-file uploads, replies, account folders and real server/user icons remain supported. GIF, animated WebP, APNG and bounded MP4-backed GIF previews animate natively without autoplay audio. General video playback controls are incomplete.

History retains up to 200 current-conversation messages. Up to six recently visited conversations (80 messages each, 2 MiB aggregate serialized payload) and twelve server channel lists (2,000 channels total) stay in a session-only recency cache. Returning to a server restores its recent channel when cached. Gateway edits, deletes and reaction updates invalidate cached conversation history; incoming messages update it. Channel changes invalidate cached guild lists. Switching refreshes cached content from Discord. Chat/channel reads take priority over queued optional metadata reads, and per-route rate-limit buckets no longer stall unrelated routes. First visits, account permissions, in-flight requests and global limits still determine latency. No chat history is persisted to disk.

A dedicated icon loader plus two general loaders prioritizes avatar/server artwork over GIF decoding. The image cache holds at most 128 textures / 48 MiB decoded pixels, with 12 MiB per decoded animation and up to 360 sampled frames per cycle. Images decode to display/DPI-sized buckets up to 1024 pixels; animated artwork is capped at 768 pixels. Avatar/icon CDN requests use 256 pixels and profile banners request 1024. Small sources are never enhanced beyond their original detail. Animation playback defaults to 60 FPS, configurable from 5–60 in Performance; source cadence and the display refresh rate remain the upper limits. Old 30-FPS defaults migrate to 60 once, preserving lower custom caps and reduced-motion choices. Under animation memory pressure, spatial resolution reduces before frame sampling; whole cached assets are evicted by recency. Timing is preserved and off-screen animation pauses. Media downloads are limited to 16 MiB; source images are bounded to 4096 pixels per side / 64 MiB decoder allocation and MP4 duration remains bounded. Unsupported/oversized media can fail to preview; original links remain available. Media receives no credentials and is not cached to disk.

The target remains roughly 200–300 MB ordinary-chat RAM, without a hard cap. Calls, captures, unusual fonts and large media can use more. Full Markdown, forums/threads, desktop notifications, complete administration and Discord feature parity remain unfinished. Measurements are short offline workloads, not live-account or long-session benchmarks.

## Build

Requires Rust 1.99+, CMake, Microsoft C++ tools and Windows SDK. In an x64 Visual Studio developer shell:

```powershell
$env:CMAKE_GENERATOR = 'NMake Makefiles'
cargo build --release --locked
cargo test --release --locked
cargo test --manifest-path vendor/serein/Cargo.toml -p discord-voice --release --locked --lib
```

Configuration/libopus use static Microsoft CRT; the EXE needs only Windows OS libraries. Media is adapted from pinned [Serein](https://github.com/ViceVerse-cz/Serein/tree/a76e030d749ef558e687bbff6dc592a7dddec244), MIT OR Apache-2.0. Sources, patches/licenses ship in vendor/ and THIRD_PARTY_NOTICES.txt.

Diagnostics: `--preview`; `--smoke-test <png>`; `--smoke-test <png> --smoke-login`; `--stress-preview`; `--preview-dms`; `--small-window`; `--preview-section timestamps|emoji|gifs|zoom-in|zoom-out|settings-zoom|server-zoom|quick-actions|server-hover|profile|settings|dm-picker|inline-logs|voice-sidebar|voice|call|friends|nitro|shop|quests|roles|plugins|themes|performance`; `--animation-check <local-media> <json>`; `--network-check <json>`; `--icon-check <json>`.

Smoke tests capture only Eclipse's own frame, save memory/cache measurements and exit. Offline call preview opens no devices and sends no signaling.
